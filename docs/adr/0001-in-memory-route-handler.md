# ADR 0001 — 인메모리 Route Handler + 순수함수 도메인 분리

- **상태**: 채택 (Accepted)
- **날짜**: 2026-05-31
- **맥락**: Crewmon 출퇴근·급여 앱(홈/출퇴근/급여 범위)을 신규 Next.js 16 App Router repo에 구현. 디자인 재현 + 동작 데모가 목표이며 실제 운영 인증/영속화는 비목표.

## 결정 A — 영속 저장 대신 Route Handler + 인메모리 store

**결정**: 외부 DB(Prisma/SQLite 등) 없이 `src/app/api/*/route.ts`(Next.js Route Handler)와 모듈 싱글톤 인메모리 store(`src/lib/store.ts`)로 데이터를 제공한다. 서버 재시작 시 시드(`src/lib/seed.ts`)로 초기화한다.

**이유**:
- 범위가 디자인 재현 + 동작 데모 — 외부 DB·인증은 명시적 비목표(사용자 결정).
- DB 셋업/마이그레이션 없이 화면·계산 검증에 집중 가능.
- API 계약(JSON shape)을 먼저 고정해, 추후 실 DB로 교체 시 Route Handler 내부만 바꾸면 됨(FE 무영향).

**결과/트레이드오프**:
- (−) 인메모리 휘발성 — 재시작 시 사용자 변경분(토글/상태변경/수정요청) 소실. → 명세된 동작으로 문서화(엣지케이스 #7, CONTEXT.md).
- (−) 멀티 인스턴스 비대응. → 데모 단일 프로세스 전제.
- (+) 외부 의존성 0, 빌드/테스트 단순.

## 결정 B — 계산 로직을 store/UI와 분리한 순수 함수

**결정**: 시간·급여 계산을 부수효과 0의 순수 함수(`src/lib/time.ts`, `src/lib/pay.ts`, `src/lib/date.ts`)로 두고, store/UI/Route Handler에서 호출만 한다. Vitest로 독립 단위검증.

**이유**:
- 급여 정확도가 앱의 핵심 가치 → 계산을 UI/IO와 격리해 독립적으로 검증 가능해야 함.
- 쟁점 C(출/퇴근 토글 = 현재시각 기록)의 비결정성을 격리: 토글은 `new Date()`를 쓰지만, 계산 함수 단위테스트(AC-1~5)는 **고정 입력값**만 사용해 결정적으로 유지.

**결과/트레이드오프**:
- (+) `pnpm test`로 계산 회귀를 즉시 포착(36 테스트 중 시간/급여/시드 불변식 커버).
- (+) 검산(390분 × 10,320원 = 67,080원)이 코드·테스트·문서에서 일관.
- (−) store/route에 얇은 어댑터 계층이 추가됨(허용 비용).
